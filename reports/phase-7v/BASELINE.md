## Additional authoritative-source discoveries made during implementation

- `calculators/index.html` (calculators hub page): initially assumed hand-authored (no generator matched the literal string in a first-pass search); a hand-edit was silently overwritten by a subsequent `npm run build`. Traced to `scripts/generate-hubs.js`, which builds card descriptions from `data/navigation.json`, itself regenerated by `scripts/generate-navigation.js` by reading each page's own `<meta name="description">`. `generate-hubs.js` runs *before* `generate-navigation.js` in `scripts/run-all-generators.js` (a pre-existing pipeline-ordering quirk, not fixed this phase -- see `REVIEW-QUEUE.md`), so two full build passes were required for the hub page to pick up the corrected calculator meta descriptions.
- `guides/ph/how-to-lower-pool-ph.html`: initially hand-edited directly; also silently overwritten by the build. Traced to `scripts/generate-authority-guides.js`, which contains this guide's content as an inline JavaScript template string within the generator itself (not a separate data file). The true fix was made in the generator source, then propagated via `node scripts/generate-authority-guides.js` followed by a full `npm run build` (to restore the nav/trust injector layer the isolated generator run does not apply -- the same known pattern documented in every prior phase).
