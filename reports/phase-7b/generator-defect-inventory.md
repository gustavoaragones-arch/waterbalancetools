# Phase 7B — Generator Defect Inventory (diagnostic, pre-fix)

Snapshot taken before any source code was changed, at commit `6df374b4b10e832503791d8f5286218806828a2c` (the Phase 7A audit commit).

## Search methodology

1. Split all `*.html` files into "production output" (everything except `templates/`, `partials/`, `components/`, `reports/`, `audit/`, `scripts/`, `data/`, `js/`, `public/`, `lib/`, `functions/`, `docs/`) and "template source" (the excluded set, which legitimately contains `{{TOKEN}}` placeholders by design).
2. Grepped production output only for: `{{[A-Za-z0-9_]+}}`, `<%= %>`, `${identifier}`, `[[TOKEN]]`, `__PLACEHOLDER__`, and literal `"undefined"` / `"null"` / `"NaN"` string values.

## Finding 1 — `{{H1_TITLE}}` (the confirmed Phase 7A defect)

- **Occurrences in production output:** 157, one per affected file.
- **Affected page families / directories:** `glossary/` (100 files), `academy/**` (48 files), `formulas/` (9 files).
- **Affected generators:** `scripts/generate-glossary.js`, `scripts/generate-academy.js`, `scripts/generate-formulas.js`.
- **Affected templates:** `templates/glossary-template.html`, `templates/academy-template.html`, `templates/formula-template.html`.
- **Affected schema types:** `DefinedTerm.name` (glossary), `Article.headline` (academy), `HowTo.name` (formulas).
- **No other token names were affected.** A full scan of production output for every `{{[A-Za-z0-9_]+}}` pattern returned exactly one distinct token: `{{H1_TITLE}}`. All other `{{...}}` names found by a repo-wide grep (`META_DESCRIPTION`, `BASE`, `SIDEBAR`, `HERO`, etc.) exist only inside `templates/`, `partials/`, and `components/` source files, which are template *definitions* and correctly contain unfilled placeholders — that is not a defect.
- **Other placeholder syntaxes checked and NOT found anywhere in production output:** `${...}`, `<%= %>`, `[[...]]`. One false-positive candidate for `__PLACEHOLDER__`-style matching was found (`printables/airbnb-pool-turnover-checklist.html`, a line of plain underscores used as a fill-in-the-blank line on a printable form) — confirmed to be intentional content, not a template artifact, and excluded by requiring at least one letter inside the double-underscore pattern.

### Example source path

`glossary/algaecide.html` (generated by `scripts/generate-glossary.js` from `data/glossary.json` via `templates/glossary-template.html`).

### Example generated output (before fix)

```json
{
  "@context": "https://schema.org",
  "@type": "DefinedTerm",
  "name": "{{H1_TITLE}}",
  "description": "An algaecide is a chemical product that prevents algae growth...",
  "url": "https://waterbalancetools.com/glossary/algaecide"
}
```

### Root cause

`scripts/template-utils.js:49`, the shared `fill()` token-substitution function used by every knowledge-platform generator:

```js
function fill(template, tokens) {
  return template.replace(/\{\{([A-Z_]+)\}\}/g, (match, key) =>
    Object.prototype.hasOwnProperty.call(tokens, key) ? tokens[key] : match
  );
}
```

The matching regex `[A-Z_]+` does not include digits. `H1_TITLE` contains the digit `1`, so the regex **never matches** `{{H1_TITLE}}` at all — the callback is never invoked for that token, regardless of whether `tokens.H1_TITLE` holds a correct value. This is a substitution-engine bug, not a data or call-site bug: `generate-glossary.js`, `generate-academy.js`, and `generate-formulas.js` all correctly pass `H1_TITLE: <the real title>` into `fill()`; the value is simply never applied because the regex silently skips over the token.

Confirmed by direct reproduction: `'{{H1_TITLE}}'.replace(/\{\{([A-Z_]+)\}\}/g, ...)` returns `'{{H1_TITLE}}'` unchanged, while `'{{PAGE_TITLE}}'` (no digit) replaces correctly.

## Finding 2 — literal `"undefined"` string in `formulas/*.html` JSON-LD (discovered during root-cause tracing, same generator)

- **Occurrences:** 9 (all 9 non-index `formulas/*.html` pages), each co-located with the `{{H1_TITLE}}` defect in the same `HowTo` JSON-LD block.
- **Example:** `formulas/alkalinity-formula.html` → `"description": "undefined"`.
- **Root cause:** `scripts/generate-formulas.js:105` — `META_DESCRIPTION: formula.description` — reads a field named `description`, which does not exist on the formula data objects in `data/formulas.json` (the real field is `metaDescription`). `formula.description` evaluates to JavaScript `undefined`; the pre-fix `fill()` implementation passed that value straight into `template.replace()`, and `String.replace` coerces a returned `undefined` to the literal text `"undefined"`.
- **Secondary effect discovered:** because the `<meta name="description">`, `og:description`, and `twitter:description` tags on these 9 pages were built from the same broken `META_DESCRIPTION` token, a later pipeline stage (`normalize-seo-metadata.js`) detected the bad value and backfilled it with scraped page text (breadcrumb + hero fragments), producing garbled meta descriptions like `"Home Formula Library Total Alkalinity Adjustment Formula Formula Example Explanation --> Formula Library 3 min read Updated 2026-06-01 Total Alkalinity Adj"`. This was a downstream symptom of Finding 2, not a separate defect — fixing the field reference resolved it without touching `normalize-seo-metadata.js`.
- **Related, same-generator issue also corrected:** `scripts/generate-formulas.js:32`, the formula-library hub page card renderer, used `f.summary || f.description` (also referencing the nonexistent field) which silently rendered an *empty* card description (via `esc(undefined)` → `''`) rather than a visible `"undefined"` string. Same root cause, different visible symptom (empty text vs. literal "undefined") because `esc()` has its own `String(str || '')` fallback.

## Finding 3 — everything else checked and clean

- No `[object Object]`, no `>NaN<`, no `"null"` JSON-LD string values found anywhere in production output.
- No other generator/template pair in the repository (`entities/`, `reference/`, hub pages, calculators, etc.) exhibited any of the searched patterns.
