# Phase 8C — Navigation Artifact Determinism & Residual Build Variance Remediation

## 1. Objective

Investigate, and eliminate if safely possible, the two remaining non-hub `data/navigation.json` record-level variances discovered during Phase 8B: the `audit/google/crawl-depth.html` entry's `description` field, and the `reports/phase-7a/index.html` entry's `description` field. This is a narrow forensic remediation phase: no navigation/hub redesign, no SEO expansion, no chemistry/calculator/content changes.

## 2. Phase 8B baseline

Phase 8B closed hub/navigation build-order convergence: Build 1 already reflects current navigation state, Build 2 and Build 3 show zero hub/index content changes. Phase 8B's own status report additionally noted, as an explicitly out-of-scope, undiagnosed observation: "two entries inside `data/navigation.json` for non-hub audit/report pages... fluctuate slightly between builds," confirmed not to propagate into any hub/index page.

## 3. Original anomaly (as reported by Phase 8B)

- `audit/google/crawl-depth.html` description: click-depth stats (e.g. "Maximum clicks: 6 · Average clicks: 2.49...") reported as fluctuating.
- `reports/phase-7a/index.html` description: reported toggling between `""` (empty) and `"Phase 7A Forensic Audit Dashboard."`.

## 5. Exact changed JSON paths

None. Across three consecutive `npm run build` invocations from the committed Phase 8A+8B baseline, no `pages[].*` field changed for either record, or for any other record. The only field that changes build-to-build in `data/navigation.json` is the top-level `_generated` ISO timestamp, which is intentional wall-clock build metadata, not a page record.

## 6. Source HTML responsible

- **`audit/google/crawl-depth.html`**: generated by `scripts/audit-crawl-depth.js`. It walks every `.html` file's `<a href>` links (excluding `node_modules, .git, assets, scripts, data, js, functions, lib, mcps, terminals, agent-transcripts, templates, partials`) and computes real click-depth statistics (max clicks, average clicks, pages above a 4-click target, unreachable pages) from the current link graph, writing them into the page body.
- **`reports/phase-7a/index.html`**: NOT generated by any script in the `npm run build` pipeline. It is a static, historically-finalized artifact. The only script capable of regenerating it is `scripts/audit-forensic/run.js`, a separate, manually-invoked forensic-audit tool.

## 7. Dependency graph

```
npm run build (scripts/run-all-generators.js)
  ├─ ... (Phase 8A/8B fixes, entity/hub/navigation generators) ...
  ├─ execSync('node scripts/audit-crawl-depth.js')   ← writes audit/google/crawl-depth.html
  │                                                      (real click-depth metric, current link graph)
  ├─ execSync('node scripts/generate-navigation.js') [Phase 8B pre-hub refresh]
  ├─ require('generate-hubs.js')
  ├─ require('generate-navigation.js')               ← walks ALL .html files (including
  │                                                      audit/google/crawl-depth.html and
  │                                                      reports/phase-7a/index.html) and
  │                                                      extracts <title>/<meta description>/<h1>
  │                                                      into data/navigation.json
  └─ ... (remaining pipeline) ...

scripts/audit-forensic/run.js   ← SEPARATE, standalone tool. NOT invoked anywhere in
                                    run-all-generators.js. Regenerates
                                    reports/phase-7a/index.html from an internal template
                                    that (in its current form) has NO <meta name="description">,
                                    canonical, og:*, twitter:*, last-updated, or content-version
                                    tags -- only <title> and <meta name="robots" content=
                                    "noindex, nofollow">.
```

`scripts/inject-seo-metadata.js` (which normally adds/normalizes `<meta name="robots">` and `<link rel="canonical">` sitewide) was independently checked: its `collectFiles()` whitelist (`calculators, programmatic, guides, legal, tools, charts, comparisons, maintenance, printables, printable, reference`) never includes `reports/`, `audit/`, or `qa/`. So no generator in the build pipeline ever touches `reports/phase-7a/index.html`'s content or metadata.

## 8. Root cause

**`audit/google/crawl-depth.html` — classification A (legitimately dynamic).** `scripts/audit-crawl-depth.js` IS part of the `npm run build` pipeline and computes a real, meaningful metric from the current site's link topology. It is currently perfectly stable (3/3 identical builds) because the underlying link graph does not change between consecutive builds of the same committed state. During Phase 8B's own investigation, the "fluctuation" this metric showed was almost certainly a comparison between genuinely different site states — Phase 8B's forensic-differential methodology intentionally compared multiple build states while validating the hub-convergence fix itself (pre-fix vs. post-fix hub link content differs, which legitimately changes click-depth). This is the metric correctly doing its job, not a defect.

**`reports/phase-7a/index.html` — classification F/H (another, non-pipeline generator; stale intermediate data), proven to be a Phase 8B testing-methodology artifact, not a `npm run build` defect.** `scripts/audit-forensic/run.js` is confirmed, by direct reproduction (see Section 9), to strip all SEO meta tags from `reports/phase-7a/index.html` when run. Phase 8B's own investigation explicitly involved running this separate script mid-sequence as part of its Section-16/18-style forensic-differential check (per the inherited project record). Running it, without an intervening restore before the next navigation-capturing build/diff step, left `reports/phase-7a/index.html` temporarily without a `<meta name="description">` tag — `generate-navigation.js`'s extraction correctly captured an empty description for that genuinely-empty on-disk state. This is not `npm run build` nondeterminism: `npm run build` never touches this file at all (proven in Section 7). The anomaly was produced entirely by a separate, deliberately-invoked diagnostic tool interacting with the investigation's own testing sequence.

## 9. Direct reproduction of the mechanism

To avoid merely asserting the hypothesis, `scripts/test-phase-8c.js` (test 5) reproduces it directly against the live repository, then immediately restores:

1. Confirms the committed `reports/phase-7a/index.html` carries `<meta name="description">`.
2. Runs `node scripts/audit-forensic/run.js`.
3. Confirms the resulting file no longer carries any `<meta name="description">` tag.
4. Runs `git checkout HEAD -- reports/phase-7a/` and confirms the file is restored byte-for-byte.

This was also run manually during the investigation and produced the same result: the regenerated file's `<head>` contains only `<meta charset="UTF-8">`, `<title>Phase 7A Forensic Audit Dashboard</title>`, and `<meta name="robots" content="noindex, nofollow">` — no description, canonical, og/twitter, last-updated, or content-version tags.

## 10. Accidental vs. intentional determination

- crawl-depth: **intentional dynamic build metadata.** It belongs in navigation.json's description exactly as-is; no consumer needs it byte-stable across builds of unchanged content, and it correctly reflects real site state when that state changes. No exclusion or normalization needed.
- phase-7a: **not a build-pipeline defect at all** — `npm run build` never touches the file, so there is nothing to make deterministic within this phase's scope. The historical fluctuation was Phase 8B's own testing artifact. Per Section 21 (no changes outside navigation-artifact-determinism scope) and Section 9/10 (preserve Phase 8A/8B architecture, do not broaden), `scripts/audit-forensic/run.js` is explicitly out of scope — it is not part of `npm run build`, and modifying a separate, non-pipeline diagnostic tool's own template (to make it also carry SEO tags) is outside "navigation artifact determinism" and was not attempted.

## 11. Exact remediation

**No source code changes were required or made.** Both records are already fully deterministic under `npm run build` (proven across 3 consecutive builds, 0 non-timestamp differences). The Phase 8C deliverable consists entirely of the required validator, test suite, and documentation:

- `scripts/validate-phase-8c.js` (new)
- `scripts/test-phase-8c.js` (new)
- `docs/PHASE-8C-NAVIGATION-ARTIFACT-DETERMINISM.md` (new, this file)
- `reports/phase-8c-status.md` (new)
